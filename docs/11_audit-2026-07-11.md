## 確定指摘（反証生存のみ・優先度順）

### A. 挙動修正レーン（1件ごとに挙動差の明文化と個別承認が必要）

- [ ] **A1【最重要】stale `.wait.lock` の回収機構がない** — `src/core.ts:1425-1449`。lock に pid/at を書くが**読むコードが存在しない**。agent_done 待機中の SIGKILL/OS 再起動で lock が残ると、同 session への `wait:"agent_done"` が EEXIST で無期限拒否。正規回復が session 破壊（pty_close/killAll）か手動削除のみ。待機窓は既定 600 秒×日常操作＝発火現実性高。Codex レビューと Workflow Critic が**独立に同着**。
  修正: EEXIST 時に lock を読み `process.kill(pid, 0)` で liveness 判定 → ESRCH なら unlink して O_EXCL retry（pid 再利用誤判定は拒否側に倒れ fail-safe）。最低限でもエラーメッセージに lock 内 pid/at を出す。
  実在証拠: state root に `pty_list` に居ない孤児 managed home（novel-a-fixtures-*）が現存＝クラッシュ残骸は実際に起きている。
- [ ] **A2 close/killAll がプロセス間 wait lock を見ない** — `src/core.ts:935-950, 952-998`。ガードは in-memory `agentWaitLocks` のみ（既存回帰は in-process 検証＝反論不成立）。別プロセスの close/killAll で、待機側は **600 秒ブロック後に空出力＋`agent_timeout`（無診断）**。
  **A1 とセットでのみ修正**（順序: A1 stale 検出 → A2 は「生きている pid の lock のみ拒否」）。A2 単独実装は stale lock が close を塞ぐ改悪。
- [ ] **A3 rtk classify の pytest 誤分類が全文を虚偽に置換** — `src/rtk.ts:403`（`command.includes("pytest")` の全文部分一致）＋ `reducePytest`（rtk.ts:62-188）は **null を返せず**、非 pytest 出力が「Pytest: No tests collected」1行に置換される（rtk.ts:369 の C4「誤分類は安全」コメントは pytest reducer に関して偽）。`python run_not_pytest.py` 等で実測再現。オプトイン経路・raw 回収可能だが、能動的に有害な失敗モード。
  修正: classify を絞るのでなく **reducePytest に「pytest 証拠ゼロなら null」ガード**（summary 行パース成功／`FAILURES`・`short test summary` 見出し／`no tests ran in` のいずれか必須）。**罠**: golden fixture 全6件は quiet 形式で "test session starts" ヘッダを含まない＝ヘッダ必須ガードは fixture を壊す。
- [ ] **A4 `pty_read` の削減に行長・総量キャップがない** — `src/core.ts:461-478, 919-922`。head+tail 折りたたみは「行数>60」でのみ発火し、**巨大な少数行**（TUI の絶対座標再描画ストリーム等）はそのまま通る。実測: Grok TUI ログ full 読みで 73,176 文字/4行が返り MCP token 上限エラー。MAX_FULL_BYTES(8MB) はメモリ保護でありトークン保護ではない。
  修正: `reduceOutput` の行数 elide 直後に文字量ガード1段（超過行に行内 head+tail＋復元ヒント。行構造は保持＝`line_range` の行番号ドメインを変えない）。screen/full/default が通る単一の絞り口で全非 raw 経路を守れる。
- [ ] **A5 `rm -rf -- /` が破壊ゲートを素通り** — `src/core.ts:77`。POSIX の `--` 終端子で対象パターン不一致（実測: `rm -rf -- /` false / `rm -rf /` true）。対象直前に `(?:--\s+)?` 挿入の1行修正。
- [ ] **A6 DESTRUCTIVE ゲートが rtk rewrite 後を検査しない** — `src/core.ts:729-773`。検査(732-742)→ `rtkRewrite`(756) で外部バイナリ stdout に置換→未検査で送信。opt-in・信頼バイナリ前提で実害確率低だが、防御の被覆漏れ。rtk 適用後に再検査。
- [ ] **A7 line_range "5:3"（下端>上端）が無言で空を返す** — `src/index.ts:147-149`＋`core.ts:881`。負値/NaN は救済済みなのに逆転のみ未処理。raw:true では説明ゼロ（既定経路は 0行メタで空自体は見える）。「フォールバック禁止」原則違反の型＝明示エラー3行＋テスト1件。
- [ ] **A8 full/range の 8MB 切り詰めが UTF-8 先頭境界を破る** — `src/core.ts:876`。増分経路の `utf8SafeEnd` と非対称。実害は先頭最大1文字の U+FFFD（cosmetic）だが対称化は S。**副産物**: agent 経路 `core.ts:2026/2078` の `writeOffset(name, safeStatSize(...))` が「off は safeEnd 済み」不変条件(892)を破り得る nit も同時に直す。

### B. 挙動不変レーン（docs/テスト/観測性）

- [ ] **B1 `force` の describe が二重ガード解除を隠す** — `src/index.ts:81`。実装は正しく、`force:true` は破壊ゲートに加え**agent 初回 prompt 混入防止ガード**（core.ts:1734）も解除するのに説明が前者のみ。describe 追記だけ。
- [ ] **B2 tools/call ディスパッチ層が完全未テスト** — `test/smoke.test.mjs` は initialize+tools/list のみ。`registerTool` 配線・isError 整形・未知ツール応答が MCP 公開契約なのに未実行。誤引数1件＋未知ツール1件のエラー系を優先追加（正常系は tmux 副作用があるため限定）。
- [ ] **B3 `pty_list` が agent metadata を出さない＝サーバ再起動後に再発見不能** — `src/core.ts:925-933`。tmux session と metadata は再起動を生き延びるのに、一覧から「どれが agent_done 対応の Codex/Grok か」を判別できない。`tryLoadAgentMetadata` を merge して kind/agent_done/vendor_session_id を追加列で出す（追加的・既存文字列互換）。
- [ ] **B4 codex managed config 継承の帰結が不可視** — 端末 config.toml **全文** copy（`core.ts:1224-1237`）により親の **mcp_servers 全テーブル**（実物11個）と **approval_policy=never + sandbox_mode=danger-full-access（=YOLO 表示）** が子へ波及し、`--dangerously-bypass-hook-trust`（core.ts:2136・agent_done 時のみ）も付く。**設計自体は docs/04:276,459・docs/10:13-14 で意図的と裏取り済み**（通常 home と挙動差を作らない目的）＝変更不要。ギャップは可視性: 起動応答は model/effort の出所しか出さない。継承 MCP 数と YOLO 相当設定を**起動応答に1行明示**する観測性追加が最小対処。
- [ ] **B5 長い TUI 回答の回収経路がない（missing feature 筆頭）** — `wait:"agent_done"` の返りは描画済み screen の tail（pane 高さ≒24行）のみで、長い回答は切れる。pipe-pane ログは絶対座標再描画の soup（実測 raw ~27.5万 tok）で line_range でも実用にならない。実運用の回避は「本人に再掲させる」多ターン。aiterm は `vendor_session_id` を bind 済みなので、**managed home 内の vendor session transcript から最終 assistant メッセージを構造的に返す read 経路**（例: `pty_read(..., agent_transcript:true)` か agent_done 返り値の `last_message`）が本命候補。設計判断が要るため起票のみ。

## 棄却台帳（反証で死んだ主な指摘・理由の要点）

| 指摘 | 出所 | 棄却理由 |
|---|---|---|
| metadata 書き込み非アトミック→管理不能残骸 | Codex | tryLoad の graceful degrade で TUI は普通 PTY として操作可・close は名前ベース削除で無影響・発火窓マイクロ秒 |
| stop hook JSONL partial write→timeout 化 | Codex | O_APPEND 原子性＋読み手の carry/malformed 診断＋回帰3本が防御済み。実害は ENOSPC-on-tmpfs 限定 |
| config quoted key 重複→Codex 起動失敗 | Codex | 全段実証済みだが quoted top-level key の実運用例ゼロ＋fail-loud（README 既知設計） |
| hook 失敗も exit 0／cleanup 握り潰し | Codex(低確度) | vendor hook 契約・close 失敗させる方が有害。診断 suffix あり |
| wait ポーリング utf8SafeEnd 未適用 | Grok | 静止判定はサイズベース・固定 start の毎 poll 再読で自己回復＝実害なし |
| 省略ノートで line_range 1行シフト | Grok | >8MiB 限定・その域では行番号基準が先に崩壊・現順序が full ビューと自己整合 |
| mark+enter:false ガード不在→必ず timeout | Critic | 誤読（quiescent が~0.5秒で発火）。ガードは正当パターン（text→pty_key Enter＝agent 経路自身の設計）を壊す |
| events.jsonl 1MB 無言 null | Critic | 到達に単一 launch 約3千ターン・被害はメタ表示のみ |
| 毎 read の metadata suffix オーバーヘッド | Critic | ~5-20ms/read で MCP 往復に埋没。誤送信防止の意図的コスト |
| zod に session 名/timeout 範囲制約なし | WF | 実行時ガードが完全捕捉・エラー同一（冗長防御） |
| agent_timeout に回復ガイダンスなし | WF | docs/04:142 で意図的設計・再送誘導はむしろ危険 |
| pytest FAILED の " - " 分割破損 | WF | rtk 0.42.0 一致契約の範囲内・fixture で考慮済み |
| Windows CI 非ブロッキングの穴 | WF | CONTRIBUTING/README/archive に3箇所明記済み＝提案が実装済み |
| ほか（nested 閾値 flaky・elide 境界・意図的相違のテスト不在・timeout ヒント） | WF | 実測余裕5倍／utf8SafeEnd 無関係／test/rtk.test.mjs:3＋test_fail_dash_reason fixture が既に固定／スキーマ文書化済み |
